# Agent notes

## Agent-managed project conventions

- Run from the repo root. Use `uv` and the project `.venv`; never install system packages with bare pip.
- The UI is static HTML/CSS/JS served by FastAPI. Node exists only for Playwright. No frontend build is required.
- Keep `README.md`, `docs/worklog.md`, and these notes current for behavioral changes. There is no database or schema.sql.
- `Game.observation()` is the only input to both Laya and reference evaluation. Never pass a Game into policy inference or include seeds, hidden ranks, or the true shoe in observations.
- Unseen counts include the hidden dealer card; peek-conditioned next-card probabilities subtract its posterior expected occupancy. Simple counts/total is wrong after a negative ace/ten peek.
- Aces use low value 1 in compact model state. All ten-valued ranks are combined. Hands retain actual rank/suit for display.
- `analyze` is Monte Carlo with basic continuation, not an exact optimal solver. Don't rename its action preference to an optimality guarantee or conflate model action preference with a win probability.
- The Laya SDK `confidence` for choice questions is normalized entropy, not the selected-label probability. Display `probabilities` directly. The SDK's `act_head` is unrelated to blackjack actions and is not used.
- Root SDK loading can fetch bundled checkpoints. `resolve_checkpoint` allow-lists root model/config/tokenizer/encoder files and pins a Hugging Face revision. Avoid broad snapshot downloads.
- Laya's `temperature_by_options` overrides per-type temperatures. Replace both when calibrating; `choice:6-10` is dealer, `choice:2`/`choice:3-5` are actions, `noul:2` is hit-bust.
- Laya sequence construction truncates silently. `ensure_fits` rejects overflow and is used by training and inference with the same 1024/256 context budgets.
- No train/validation/test game-seed overlap. Validation fits temperature; test only reports. Saved reports label probability distance to the approximate teacher, not empirical casino win calibration.
- Use new artifact directories; publish complete checkpoint directories by rename. Do not commit model binaries, datasets, secrets, or environment files.
- FastAPI routes are sync functions so CPU rollouts and PyTorch work run off the event loop. Lock table mutations and check revisions. Loading/prediction share a model lock; failed loads preserve the existing model.
- Session metadata, model loading, and jobs are in-process. Use one Uvicorn worker. The app is a localhost personal lab, not a multiuser deployment.
- Unit/card-conservation and hidden-state invariance tests are critical when changing engine or policy code. CI must work without Laya extras or checkpoint downloads.
- Shuffle and tablemate behavior use separate RNG streams. Replaying explicit actions does not call the behavior policy, so sharing its RNG with shuffling corrupts later shoes even when early replay rounds match.
- Large experiments use four group-disjoint splits: training, epoch/candidate selection, temperature calibration, and final test. Fixed pre-training test metrics are recorded for comparison but never drive selection, stopping, or hyperparameters within a run.
- Adaptive common-world Monte Carlo uses a three-standard-error stopping heuristic. Label it as a heuristic, not a formal confidence bound; noisy action targets receive lower training weight.
- Fast rollout cloning must preserve RNG state AND alias relationships. Regression tests compare complete public outcomes to deepcopy plus public-observation policy calls for all tablemate policies.
- Dataset shards have atomic completion receipts, content hashes, deterministic group seeds, and a source-code/parameter plan. Never resume with a changed plan. Token caches are bound to shard hashes and the tokenizer/context contract.
- Large optimizer checkpoints include model, optimizer, RNG, exact epoch/shard/batch cursor, and training/source hashes. Keep the venv interpreter path without resolving its symlink. Publish best weights plus selection records together through an atomic pointer; publish complete candidate directories by rename.
- Overnight artifacts live under artifacts/overnight, outside dashboard checkpoint discovery. A selection winner is a candidate, not automatic authorization to replace the live model. The existing API blocks additional experiment jobs while the overnight heartbeat is active or stale.
- Overnight supervision retains the original deadline when resumed. Production local launches additionally use systemd RuntimeMaxSec and KillMode=control-group; preserve an immutable source snapshot per run. No other GPU processes may be stopped.
- Release packages include a per-file SHA-256 inventory and the state/question contract digest. Pin the Hub commit AND manifest digest in `blackjack/model_release.json`; download, verify, and install atomically before loading. Keep optimizer state and binary data out of Git.
- Checkpoint discovery must exclude hidden and `.staging` directories: a copied training report alone does not make an in-progress installation eligible. Failed loads preserve the existing live model.
- Paired policy evaluations use fixed equal-weight rule strata. Fresh rounds are independent units; continuous play uses independent 100-round blocks. Compute paired differences using exact matching scenario/index keys, with uncertainty over units rather than correlated hands.
- Preserve evaluator source hashes, model/config hashes, raw return shards, and receipts. Resuming with a changed evaluation configuration fails. Research supervisors are bounded, run in separate process groups, and appear in the dashboard Research run panel.
- BF16 batch shape can change near-tied argmax decisions. Fast action-only evaluation falls back to the exact three-question SDK call for raw top-two logit gaps under 0.15. This matched all 5,000 release test states; it is an empirical guard, not a universal parity guarantee. Keep trainer and serving measurements distinct.
- The release test set has now been inspected for error analysis. Future tuning must use a new locked test set. Fresh-world rechecks of selected errors are descriptive, with individual, unadjusted intervals.
- Update the model card, release results, and plotting inputs together. `scripts/plot_results.py` regenerates standalone figures from committed reports; `scripts/publish_model.py` verifies the personal identity and only writes private HF repositories. Public visibility changes are separate from private preparation.
- The `composition-v1` dataset profile uses separate seed namespaces and equal complete general/depleted shard pairs for training, selection, and final test. Calibration uses general games only. Its public-state focus requires at least 50% shoe depletion plus a hard 9–16, extreme true count, or split opportunity; focused games use 85% penetration. Never bypass the engine's early-shuffle reserve to fabricate deeper states.
- Targeted training passes `--defer-test`: neither baseline nor candidate predicts the final test during training. Both candidates are frozen in `selection-frozen.json` before SDK audits. Metadata/hash verification may read rows but must not compute test predictions. Do not reuse the inspected release test for tuning or a new final claim.
- Guarded checkpoint selection includes the unchanged source as epoch zero. Eligible epochs must improve depleted and overall selection regret, with general regret no more than 0.0005 units above the source. This is a predeclared point-estimate guard, not a statistical noninferiority conclusion.
- Raw targeted candidates retain `test_deferred=true`; dashboard discovery and release packaging exclude them. After final audits/returns, a separate atomic `evaluated-candidate` contains serving metrics while preserving the immutable pre-test records. Weights/calibration and audit identities must match frozen hashes. Promotion remains separate from experiment completion.
- Smoke runs add 10,000,000 to the root seed. Their test games and return units must not overlap the real experiment. Resuming targeted supervision uses the original deadline and immutable source/configuration; budget exhaustion never grants a fresh 12 hours.
- Owner release scope: one final public model selected after research. Keep experiment weights and existing preparation packages private, including their Hub revision history; replacing main's weights does not remove historical checkpoints. Preserve private backups and stage a clean final model history before publication. Comparative evidence may be public without intermediate weights.
- The completed composition-v1 test has been inspected. It improved reference imitation without a resolved return gain; use fresh final-test games for future tuning. Diagnose both disagreement counts and regret contributions: unresolved labels dominate disagreement counts, while resolved mistakes still contribute most measured regret. Reference separation is a sampling heuristic, not proof of optimality.
- `exact_reference.py` supports one player/one unsplit hand with no legal split. Its Bellman maximum is over the public posterior, never inside a known-hole branch. Dealer recursion removes cards without replacement; player draws subtract posterior hole occupancy. Unsupported states and deterministic 50,000-node overruns use an explicitly marked Monte Carlo fallback. Preserve engine void semantics and include reference-kind coverage in reports.
- `targeted --study teacher-cost` offsets the root seed by 20,000,000 and adds the teacher to game-seed namespaces. Both GPU arms use the same 5e-6 learning rate/data/seed, comparing imitation and cost-sensitive loss. The action penalty is 0.25 times expected capped regret divided by 0.1 unit; other probability tasks are unchanged. This does not isolate teacher effects from additional data/training. Cache contract version three includes reference-kind metadata.
- `research --seed` freezes complete evaluated checkpoints into its own private `checkpoints/` directory, binds tokenizer/encoder/calibration as well as weights, and checks those identities before comparisons. Resume uses the original run deadline/configuration under an exclusive lock; old-format runs need their original source snapshot. Never change sample counts or extend the budget based on interim results.
- Evaluation receipt version two preserves per-shard serving-fallback counts across resume. Large-return uncertainty uses independent rounds or 100-round blocks. `summary.json` includes Bonferroni-adjusted intervals over the four planned aggregate comparisons; scenario intervals remain exploratory. The current frozen large study uses seed 20261001; its smoke uses 30261001.
- The completed large-return analysis reproduces both reports from hash-verified raw units before export. Keep the four predeclared aggregate contrasts separate from the forty exploratory scenario contrasts and twenty-five selected-error rechecks; corrections are within each stated family. Return artifacts lack decision traces, so separate enriched audit errors cannot explain the return gain causally. An exact optimal-continuation label cannot be validated with a basic-continuation Monte Carlo recheck; the mixed-teacher error diagnostic explicitly excludes exact cases. Research figures and metrics must not be attributed to the older downloadable checkpoint.
- `visitation-pilot` is development-only and never exports a training/final-test manifest. Reservoir sampling and hero behavior have RNGs separate from shuffling; changing sample counts cannot change play. Replay metadata stays outside policy observations. Partial collection resume must replay original inference batches, including already completed groups, because removing groups can alter BF16 actions. Label/audit receipts bind to collection hashes; completion and qualification are distinct. Full seed 20261002 and smoke seed 30261002 use a new namespace, and threshold failures must remain visible rather than being relaxed after inspection.
- The standard visitation pilot completed but failed the preset 80% both-resolved gate (Laya 78.00%, mixture 80.05%). Preserve its report. One stronger-budget follow-up uses fresh seed 20261003 and `--label-budget strong` (2,048–16,384 worlds; smoke still 32–64), with unchanged counts/gates and a one-hour cap. Budget choice is part of the immutable run identity; a new sample plus new budget is not a matched estimate of the budget effect.
- Reference research sampling is bounded by shared `MAX_REFERENCE_SAMPLES=16384`; dashboard request limits remain 2048. Budget-option tests alone do not prove downstream acceptance: execute the real hybrid-to-Monte-Carlo fallback at the maximum. The initial strong-pilot attempt failed before labels at the older 10000 cap; its corrected launch must preserve the original overall deadline and planned seed.

- `scripts/export_visitation.py` reproduces reports with `write_report=False`, validates frozen checkpoint/source identities and receipts, and writes portable evidence outside the immutable run directory. Never overwrite a historical report to make recomputation agree. Direct CLI runs without archived source must retain `source_snapshot_verified=false`.

This qualifies the data pipeline, not a new model: weights are unchanged, and standard/strong pilot state samples differ. `docs/model-visited-training.md` fixes two 32,000-state arms, shared fresh evaluation, seed 20261004 (smoke 30261004), and an 800,000-round screen. - `visitation-train` implements the prepared matched study through `visitation_data.py` and `visitation_study.py`. Both arms share byte-identical broad training and held-out rows; their training manifest hashes intentionally differ. Audit all three models against the common broad manifest and verify held-out shard hashes across both trainers before comparing them. Never bypass this distinction by equating full dataset hashes.
- Matching state counts does not guarantee matching updates: require identical training shard-size sequences and verify full epoch/update completion for both arms. The incumbent is an explicit overall selection option; a partial faster arm cannot win by default. Both raw candidates stay `test_deferred=true`, and one global freeze must precede every SDK final-test call.
- Replacement labels use a content hash of the public observation within a matched initial group, independent of behavior arm. Reuse one label for identical observations; keep group seeds and replay metadata outside model state. The study seed namespace is `model-visitation-training-v1`, with roots 20261004 and 30261004 (smoke). SDK audit receipts bind calibration/tokenizer/encoder as well as weights and common test data.
